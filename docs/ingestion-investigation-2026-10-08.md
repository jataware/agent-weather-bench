# Rainfall delivery reconciliation investigation, 8 October 2026

`native-rainfall-reconciliation` is an executable, bounded candidate for the tooling-benefit experiment. It asks for a scientifically ordinary output: how did the ensemble-mean rainfall forecast change over the same calendar weeks and region? The intake involves a provider-native cumulative Zarr delivery and a curator-derived interval-mean rate NetCDF delivery. Four mm arrays and one wetter/drier claim per period use the existing envelope.

The source weather is real ECMWF forecasting data from the previously hash-frozen Kenya public archive, issued 20 and 27 September 2026. The current source retains every provider object byte-for-byte. The older issue is explicitly transformed into irregular one-/two-day interval means, with exact time bounds and reversed spatial axes. Native cumulative endpoint amounts remain exactly recoverable for every supplied interval. Both channels come from the same model; they are not independent forecasts, and the derived channel is not presented as an original provider-native product. The transformation and original object hashes are in the agent-visible provenance. This narrower task avoids introducing an unverified rate product: the available local CFS seasonal predictor files have unresolved source scale and are unsuitable for physical rainfall reconciliation.

Three instances cover the service region, coast and north-west, with two valid weeks each. The initial agent experiment should use `service-area--weeks-1-2` in all three environments. A second instance is useful only if a scientific failure or plausible tool benefit justifies another batch. This is a small acquisition-free integration experiment; any improvement should not be generalized to live data discovery or acquisition.

The grading design has just two convention decisions: actual interval duration versus summed rates, and same valid calendar dates versus same lead windows. The native source has tiny negative quantization increments; either retaining signed net differences or clipping those daily dips is accepted and documented. This accepted choice brings the total to eight readings, without introducing another pitfall. An independent implementation uses scalar labelled lookups, daily cumulative increments and Python `math.fsum`, without importing the vector implementation. Known-correct controls include both implementations, float32 result delivery, clipped native quantization increments and reversed coordinate/dimension order. Fault controls isolate the two scientific pitfalls, false direction claims, cached output and dependence on a non-authoritative draft bulletin. Reruns regenerate outputs, follow independently changed physical weather inputs and ignore changes to that bulletin. There are no withheld observations and no skill ranking. The template-owned source-lineage prose review is supplementary, with computational completion visible separately.

Rhiza's deaccumulation helper directly applies to the current native cumulative delivery, including source mass-per-area units. acmadDL's `normalize` directly supports accumulated daily S2S precipitation and canonical coordinate/member names; its region selection can help as well. Neither tool automatically finishes the irregular interval integration and same-valid-date comparison. Applying seasonal/monthly aggregation to this previous delivery would be inappropriate. A direct Docker probe on the actual native source verified first-week physical totals: Rhiza clipped daily rates agree with the matching accepted integration within 9.3×10^-7 mm, and acmadDL signed daily deaccumulation agrees exactly with cumulative endpoints. Both processes exit cleanly. The local record is `var/review/ingestion-tool-physical-probe.json`; these functional probes are not agent attempts or proof of a tooling benefit. The task does not require any particular library. Actual use, correctness, time and token measurements must distinguish a tool being present from a tool helping the agent.
