Independent review of the two parallel investigations

This review separates a usable tool bundle from a scientifically difficult forecasting task. The existing MAM result is already a valid Luna computation in Python; its earlier tool-arm failures were API discovery and context-budget failures. Neither establishes a scientific capability boundary. This review makes no model calls. The narrow, archived v2 probe repair described below is the only task-contract change in this review; its validation uses one fresh scientific worker at a time.

The efficiency intervention is appropriate for the stated product question: concise public-API guidance, executable synthetic examples, and installed acmadDL/AfricaS2S. The guide contains no benchmark source paths, reference answers, target observations, or private scores. Its synthetic data exercise normalization and calibration without solving the real instance. The earlier actual-data parity checks already establish that the supported helper operations implement this task's accepted recipe. This comparison measures the bundle, including its documentation; it cannot isolate the causal effect of library code alone.

The new comparison should retain fresh workspaces, the same Luna backbone and reasoning setting, pinned CLI, task/source contract, CPU/memory, command/time limits, and all token caps. Both arms should retain every assigned attempt, including budget failures, incomplete submissions, and failures to use required helpers. The existing study's four trials remain historical evidence; a new guided attempt should not replace either earlier tool failure. An informative first pair can justify one declared replication pair. A repeated pair on the same data tests repeatability on that job, not transfer to a new scientific instance.

Two concrete implementation findings were sent to the efficiency owner. The old study summary recognizes tools by the substring `required-accord`, which would misclassify a newly added `accord-guided` system unless the new summary uses explicit arm membership. Also, the original guided instruction claimed that remaining fresh/output budgets were visible, while tool results expose cumulative tokens and remaining time/calls. The new guided wording now accurately distinguishes declared caps from displayed counters.

Token accounting must take the final cumulative provider counters once per attempt. Cached input is a subset of total input; reasoning output is already included in output. Fresh input plus output is a useful resource measure but is not a dollar cost. For an optional API list-price equivalent, ordinary input, cached reads, cache writes and output have separate rates. The official formula subtracts both cached reads and cache writes from ordinary input. If the optional cache-write counter is absent, its cost contribution is unknown rather than zero. Subscription invoice cost remains unknown. These details are supported by [OpenAI's caching cost example](https://developers.openai.com/api/docs/guides/prompt-caching/) and [the Luna model page](https://developers.openai.com/api/docs/models/gpt-6-luna).

Scientific validity and native-tool compliance need separate results. Running the synthetic demo or importing a package does not demonstrate substantive use. The frozen submitted calculation must consume normalized rainfall from acmadDL and calibrated probabilities from AfricaS2S. Inspect the actual return-value flow, executable call sites, report pointers and reruns. An ignored-helper submission remains assigned to its original arm. Report scientific completion, compliance, fresh/cached/output tokens and elapsed time even when these measures disagree. A threshold such as ten percent is an exploratory replication trigger, not a significance test or proof of savings.

The hard-task proposal is a canonical retrospective forecasting question: fit using 1993–2004 and issue twelve blind MAM outlooks for 2005–2016, leaving calibration and model combination to the system. It can be graded without a prescribed answer by checking validity and scoring withheld observations independently. The source boundary must change: the earlier task's pre-2016 observation file includes 2005–2015 and therefore contains most of this new target. The new provider must contain only training observations through 2004. All twelve target years belong outside the source service and actor mounts. Existing source snapshots should remain immutable.

The scientific target and expert selection must be frozen from training-only validation before private test scores or model attempts. A fixed expert can then establish whether the target is attainable on the withheld years, but a poor private result must not cause the method, threshold, year split or service cells to be retuned. Include fixed climatology and the existing equal-centre calibration as interpretable comparators. Beating a weak expert that loses to climatology would not by itself make the task difficult. Twelve years of training can limit calibration; poor out-of-sample skill may reflect weak information rather than reasoning failure.

Eighteen neighbouring cells do not provide eighteen independent replications per year. Report yearwise score differences and uncertainty at the year/block level. Explain that these are fixed-trained retrospective outlooks using final-vintage archives, rather than an operational system receiving newly released observations. A scientifically valid Luna forecast that misses an attainable, locked target is informative evidence for the hard track. An invalid, budget-stopped or infrastructure-failed attempt needs that specific diagnosis. One failure still does not establish an inherent capability boundary.

The efficiency plan and all four named configurations subsequently passed read-only prelaunch review. `experiments/efficiency_plan_2026-10-08.json` records explicit Python/guided arms and replica IDs, identical adapters and limits, the fixed task fingerprint and resource accounting. `efficiency_run.py` checks those hashes, the known-correct Docker proof and pinned CLI before launching a cell. The primary pair and at most one conditional replication pair are bounded in advance. Post-attempt helper-use and frozen-artifact review remain necessary.

The hard-task owner has clarified that climatology is a valid forecast. The new task will therefore omit an unconditional response-to-inputs requirement, which could reject a legitimate constant baseline. Replay and a future-predictor causality probe remain. Its performance criterion will compare with both uniform climatology and a train-selected expert. Expert selection uses five chronological development years, 2000–2004, over four single centres plus equal-centre blending and predeclared shrinkage values. This is a scientifically interpretable design; its actual source split, private score, locked selection record and controls still require artifact review. If the selected expert is just uniform climatology, or the fixed criterion lacks an attainable meaningful positive control, report that finding before claiming a hard candidate.

The initial efficiency pair exposed a precision bug and a separate controller defect. Both frozen implementations sum CHIRPS monthly float32 values before casting their seasonal observations to float64. A trusted reproduction using that order explains every one of their seventeen delivered variables within the existing error bounds; probability residuals are at most 1.34×10⁻¹⁵. Their observation totals differ from the float64 computation by 2.2891×10⁻⁵ mm, above the declared 2.2204×10⁻⁶ mm bound. This is a small precision deviation under the requested float64 computation, not evidence that either system failed to understand calibration.

The held-out probe's leakage accusation was confounded. It multiplied the entire observation field after promoting it to float64, thereby changing aggregation precision for otherwise untouched training years. The frozen algorithms then changed the held-out forecasts by about 3.58×10⁻⁸ despite correctly excluding that year's observation. A same-dtype perturbation leaves those forecasts exactly unchanged. The [independent diagnostic](../var/review/efficiency-precision-review-20261008/diagnostic.json) records both findings separately and does not execute model-written code on the host or modify frozen submissions.

After the parent archived the complete v1 contract, the authorized narrow v2 repair casts perturbed source variables back to their original dtype for both probe kinds and increments the spec version. New regression tests verify unchanged source precision, byte-identical untouched records, continued catalog validity, acceptance of a properly isolated fold, and detection of leaked thresholds. The repair preserves the precision requirement and numerical tolerances. The original assessments remain attached to v1; any later assessment or clearer-instruction experiment needs its own versioned evidence. Neither invalid initial submission can count as a valid efficiency gain.

The first hard candidate's locked expert did not generalize: its withheld RPS is 0.478486, worse than uniform climatology's 0.442901. Independent score disagreement is at most 5.55×10⁻¹⁷. Because uniform climatology meets the declared match-or-beat-both criterion on this split, this candidate does not establish a difficult performance target. The owner stopped before inference and did not retune the method, split or threshold after seeing private scores. Keeping that negative result is more informative than relabelling the split as a capability test.

Original guided execution traces independently support substantive native-tool compliance: returned acmadDL seasonal fields feed the submitted model means and AfricaS2S receives those fields and supplies submitted probabilities. Five real-data command invocations imply seventeen normalization calls and eight calibration calls, including the first failed rename and two later RPS-shape failures. These are counts inferred from recorded command paths and error positions, not instrumented dynamic counters. Synthetic examples and controller replays are counted separately. Compliance does not rescue the original precision failure.

The second proposed pilot, `seasonal-objective-consolidation`, is a lean final probability-consolidation question over genuine local ACMAD-replication components. Its contract explicitly distinguishes equal-component headline weights from nominal-count sensitivity and makes no observation-verified skill claim. Read-only review finds consistent complete-vector support, normalization and disagreement semantics between NumPy and scalar references. Source hash/grid verification and the targeted partial-vector fixture remain necessary. This appears straightforward; one valid Luna result should end this candidate investigation without adding requirements or calling it a capability boundary.

An actual hardened Docker correct-control assessment then passed every one of ten computed instruments, including fresh changed-source retrieval and held-out isolation. This is exploratory evidence of valid-completion benefit for the documented tool bundle under this budget, not a replicated speedup, invoice saving or general scientific capability boundary.
